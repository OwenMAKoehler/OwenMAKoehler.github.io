LVAD Power Cycling Fixture.

Abbott Heart Failure, Systems Engineering Co-op, January to August 2026

This fixture automates power cycling on an LVAD system, which makes long-term testing possible without an operator. The project was started in 2023, but had stalled and never been completed. I was the technical lead on a team of four co-ops, responsible for redesigning the hardware, rewriting the firmware, and getting it running.

The problem

Long-term LVAD testing means switching the power source regularly to keep the controller alive. Before this project, an operator had to step in by hand to keep each test going. An automated fixture had been started to fix this, but it was never finished.

Tools: Arduino and C++, relay control, microSD data logging, hardware design, verification testing

What I did

  • Technical lead: I led the technical work for a team of four co-ops, taking the fixture from a stalled prototype to a working test system that runs on its own.
  • Redesigned the hardware: I added a rotary encoder with a push-button and a microSD data-logging system. Operators can now configure each test directly at the fixture, such as selecting how many batteries are present and what cycle to perform, instead of reprogramming it. The original fixture also had no way to record data. My logging system saves results in a format that imports directly into Excel, letting engineers plot battery performance against cycle count for the first time.
  • Rewrote the firmware from scratch: I rebuilt the control software in Arduino C++ with a modular architecture. It adapts to anywhere from 0 to 5 batteries based on what the user enters. Pressing and holding the rotary encoder during a test opens a pause menu, where the operator can skip the current step, make the current cycle the last one, end the test, or cancel and resume. Every menu action is recorded in the debug log.
  • Built automatic logging: The fixture writes two files to a microSD card. DRAIN.CSV records how long each battery and the controller lasted on every drain cycle, and DEBUG.LOG records everything else.
  • Added a detailed debug log: DEBUG.LOG timestamps everything the fixture does: each boot, which batteries and cycle type were selected, every menu action, power source switches, and when each drain starts. It gives a complete picture of what the fixture was doing and when. Every power-up is numbered by a boot counter saved in the Arduino Mega's permanent memory (EEPROM), so restarts are easy to spot.
  • Made the SD card removable mid-test: The card can be pulled out at any time to check the data. While it's out, new lines are held in RAM and written as soon as it's plugged back in, so no data is missed.

Three cycles of data from a four-battery test. The empty column is the unused fifth slot.

Result

The fixture now runs power-cycling tests with no operator involvement, saving an estimated $500K in testing costs. Because the architecture is modular, the fixture can take on new test configurations without being redesigned.

I also calibrated equipment and ran HeartMate 3 LVAD verification tests. I ran outflow graft permeability tests as well, which evaluate how the sealant performs under physiological flow.
